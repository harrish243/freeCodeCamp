# --description--

In the last lesson, you learned that variables are references to objects in memory. The behavior of these objects depends on whether they are **mutable** or **immutable**.

**Immutable** objects cannot be changed once they are created. Examples include integers, floats, strings, and tuples. If you try to modify them, Python will instead create a completely new object in memory and update the reference.

**Mutable** objects can be changed *in place* without creating a new object. Examples include lists, dictionaries, and sets. 

Because multiple variables can refer to the *same* mutable object, changing the object through one variable will cause the change to be seen by all other variables referencing it.

```py
# Immutable example
x = 10
y = x
x = x + 1 
# 'y' is still 10, because 'x' now points to a new object '11'

# Mutable example
a = [1, 2, 3]
b = a
b.append(4)
# Both 'a' and 'b' now point to [1, 2, 3, 4]
```

In the mutable example, `a` and `b` share the same exact list object in memory. When `.append()` mutates that object, any variable pointing to it will reflect the change. This is a common source of bugs for beginners, and visualizing this memory graph is a great way to understand the program state.

## --text--

What happens when you assign one variable referencing a mutable list to another variable, and then mutate the list?

## --answers--

The second variable gets a completely independent copy of the list.

### --feedback--

Assigning a variable to another creates a shared reference, not a copy.

---

Both variables reflect the mutation because they share a reference to the exact same list object in memory.

---

The program throws an error because two variables cannot point to the same list.

### --feedback--

Python allows many variables to point to the same object.

---

### --feedback--

Since they share the same object, mutations affect the underlying object both variables point to.
